Permission policy output
========================

.. note::

   Historical development record. Last source update: 2026-10-16.
   This record does not define a supported schema or file format and has not
   been reviewed by a human for current accuracy.

django-trusts can render its registered authorization policy as reviewable
output containing generated parameterized SQL. The output is one-way: it helps
reviewers inspect the queries and notice changes, and django-trusts does not
consume it as a policy input.

Current user instructions live in the `setup guide
<../source/index.rst#permission-policy-in-sql>`_. Current security boundaries
live in the `security audit
<../../SECURITY_AUDIT.md#authorization-policy-sql-and-lockfile>`_.

Inspecting and locking output
-----------------------------

Inspect the current output after application registration:

.. code-block:: console

   python manage.py trusts_policy_sql

Write the same current output to the application's lockfile:

.. code-block:: console

   python manage.py trusts_policy_sql --lock

Run the Django system check in CI and before deployment:

.. code-block:: console

   python manage.py check

``trusts.E009`` compares generated bytes with the committed lockfile. It is a
change-detection mechanism, not a request-time authorization gate.

Security boundaries retained from the implementation work
-----------------------------------------------------------

* The SQL formatter accepts only the tokens it understands and fails closed on
  unexpected input.
* One lockfile belongs to one selected database renderer.
  ``TRUSTS_POLICY_DATABASE`` selects the inspection alias; Django's ``default``
  alias is used when it is unset.
* Rendering does not execute authorization queries or read grant rows, although
  database-driver initialization may still open a connection.
* Output is stable only while the django-trusts version and dependencies such
  as Django and the YAML library remain the same.
* Lockfile equality does not prove compiler correctness, trustworthy
  application data, the absence of bypasses, or equivalence between database
  renderers.

The output's internal keys, ordering, identifiers, parameter notation, YAML
layout, and grouping may change. They are implementation output, not a public
contract. Review the generated SQL itself and any diff caused by policy,
django-trusts, Django, database-driver, or YAML-library changes.
