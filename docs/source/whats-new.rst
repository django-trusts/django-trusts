What's new
==========

This is the concise index of user-visible django-trusts changes. Entries are
grouped by release version or development milestone and point to the complete
feature documentation. Small fixes may point directly to their pull request.
Each feature gets a one-to-three-line summary. Planned work is added only when
its user-visible surface lands; a design document alone is not a shipped
feature.

Migration instructions remain in `migrates.md
<https://github.com/django-trusts/django-trusts/blob/dev/migrates.md>`_. When a
change appears in both places, this page says what changed and the migration
record explains what an existing application must do.

Version 1.0.0 is frozen at the ``v1.0.0rc1`` feature set. This index
therefore begins with the post-rc1 changes in the 1.1.0 development milestone.
Older history remains available through the repository's release tags.

1.1.0 (in development)
----------------------

Permitted content querysets
~~~~~~~~~~~~~~~~~~~~~~~~~~~

``QuerySet.permitted(permission, user, conditions=())`` filters an application
queryset to the protected objects one principal may access. See the `permitted
queryset inquiry contract <https://github.com/django-trusts/django-trusts/blob/dev/docs/permitted-queryset-inquiry.md>`_.

Reverse permission inquiry
~~~~~~~~~~~~~~~~~~~~~~~~~~

``content.get_permitted_users(permission)`` and the optional user-manager
adapter return the users permitted on one saved object. See the `reverse
permission inquiry contract <https://github.com/django-trusts/django-trusts/blob/dev/docs/reverse-permission-inquiry.md>`_.

Explicit Django group registrations
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``register(group=...)`` declares a path to ``auth.Group`` and keeps
group-derived enumeration distinct from direct permission paths. See
:ref:`register-the-trust` and `PR #254
<https://github.com/django-trusts/django-trusts/pull/254>`_.

Permission collection terminals
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

A ``permission=`` path may end on one forward many-to-many collection of
``auth.Permission`` after zero or more forward to-one steps. See
:ref:`register-the-trust` and `PR #264
<https://github.com/django-trusts/django-trusts/pull/264>`_.

Permission content-type isolation
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

An ``auth.Permission`` grants only on content with the same Django content
type; crossed permission/object pairs now deny. See the `migration record
<https://github.com/django-trusts/django-trusts/blob/dev/migrates.md#permission-content-type-must-match-the-object-267>`_.

Authorization policy SQL and lockfiles
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``trusts_policy_sql`` renders registered permission inquiries as reviewable
SQL, and ``trusts.E009`` can compare the generated bytes with a committed YAML
lockfile. See :doc:`authorization-policy-sql`.
